# Phase 1 — Divergent exploration

Volume assumption used in every cost cell: **50 episodes/show, one new show per week = 2,600 episodes/year.** Median episode = 10.6 KB ≈ 2,650 tokens; the whole 50-episode pack ≈ 132K tokens. Price anchors (vary by source and date, cited not invented): Gemini 2.5 Flash-Lite ≈ $0.10/M in, $0.40/M out; 2.5 Flash ≈ $0.30/M in, $2.50/M out; free tier for Flash-Lite ≈ 15 req/min, 1,000 req/day ([pricing guide](https://costgoat.com/pricing/gemini-api), [free-tier guide](https://www.aifreeapi.com/en/posts/gemini-api-free-tier-complete-guide), [2.5 Flash matrix](https://rapidevelopers.com/ai-api-limits-performance-matrix/gemini-2-5-flash)). Content rephrased for compliance with licensing restrictions.

**Headline finding that shapes every option: tokens are not the scaling cost.** Even the most wasteful design below costs cents per show. The expensive resource is the editor's attention, so the design question is "how few candidates can a human trust-check per show", not "how do we save tokens".

## Problem 1 — Find the Promos

| # | Concept | LLM / code / human | Input → output | Build | Unseen-input demo | How I'd evaluate | Cost @ 2,600 eps/yr | Main failure modes | Distinctive vs median candidate |
|---|---|---|---|---|---|---|---|---|---|
| **1A** | **Whole-episode prompt.** Paste the full screenplay, ask for 3 promos as JSON. | 95% LLM, thin code, no human gate | 1 screenplay → 3 promos w/ timestamps | 0.5 h | Yes, trivially | Eyeball it | 1 call/ep, ~2.9K in + 600 out → **$0.03/show, ~$1.5/yr** (Flash-Lite) | **Invented timestamps** (model writes `01:12.40` that exists nowhere); promos drift outside 20–60s; ignores cross-episode; no reason to trust the ranking | This *is* the median candidate. Zero distinctiveness. |
| **1B** | **Parse → enumerate windows → LLM picks beat IDs.** Deterministic parser yields timed beats; code enumerates every 20–60s window snapped to beat boundaries; cheap features shortlist top-K; LLM chooses among K **by beat ID only**, never by writing a time. Code converts IDs → timestamps. | Code for time, LLM for judgment, human approves final list | 50 screenplays → ranked promos, every timestamp provably from the file | 2 h | Yes, parser is format-driven not content-driven | Validator: every emitted timestamp must exist in the parsed beat table; length in [20,60]; hook within first 3s | 1–2 calls/ep → **~$0.05/show** | Window enumeration explodes if beat density is high (handled: snap + stride); K too small hides the best promo; parser breaks on the ep-24 inline-scene-header hazard | Timestamp hallucination becomes *structurally impossible*, not "mitigated by prompting". Demonstrable with a validator that prints 0 violations. |
| **1C** | **Tension curve from tone tags (contrarian: ranking by code, LLM writes only copy).** 99.4% of dialogue beats carry tone tags (620 distinct: cold, screaming, desperate…). Map tags → intensity, add SOUND FX density and ACTION verbs, build a per-second intensity curve per episode; promos = windows with a hard spike in the first 3s and a rising edge ending at an unresolved local max. LLM only writes hook/cliffhanger/why-line. | Code decides *what*, LLM decides *how to describe it* | Beats + tone lexicon → curve → windows → copy | 2.5 h | Yes, but degrades on a show without tone tags — must detect and fall back | Curve plot vs my 3 hand-picks; ablation: does removing tone tags change the top-5? | 1 call/promo ≈ 10 calls/show → **<$0.01/show**; runs offline if copy is templated | Tone lexicon is my judgment calls (620 values, long tail); a shouting match scores high but may be incomprehensible standalone; format-dependent | Uses a signal in Kuku's own data that most candidates will never notice. Fully explainable and cheap. Weakness: brittle if another show's screenplays lack tone tags. |
| **1D** | **Verification-first: blind cold-viewer gate + pairwise tournament.** Generate candidates any way, then (i) hand *only the promo text* to a second model instance with no episode context and make it answer who/what's at stake/what question am I left with/would I watch, (ii) rank survivors by Swiss-style pairwise LLM comparisons rather than absolute scores. | LLM as the *test*, code runs the tournament, human reads the failure report | Candidate promos → pass/fail + ranked order + comprehension transcript | 1.5 h on top of 1B/1C | Yes, and this is the demo that lands: show a promo failing its own comprehension test | The gate *is* the eval: comprehension pass-rate, agreement with my hand-picks, rank stability across two runs/models | ~1 call/candidate + ~n·log n comparisons: 25 candidates → ~40 calls/show → **~$0.02/show** | Cold-viewer model is a generous grader (needs a deliberately strict rubric); pairwise ranking is non-transitive sometimes; doubles call count | Operationalises the brief's third rule ("makes sense on its own to someone who has never seen the show"). Most candidates will *claim* standalone-ness; this one **measures** it and produces a transcript as evidence. |

Dropped: cross-episode thread stitching (needs reliable character-identity resolution across 64 inconsistent speaker labels — a 3h+ problem on its own; keep as "next steps").

**The uncomfortable answer on P3:** none of 3.1–3.4 clears the brief's own bar of "why it matters *more* than Problems 1 and 2". The brief tells me promo-picking is a manual bottleneck against weekly releases, which is a stronger, Kuku-stated claim than anything I can establish about label hygiene in 7 hours. Public sources agree that the first 3 seconds are the acquisition lever: vertical hook-ads are built by ripping the most addictive opening out of an episode ([Flicknexs](https://blog.flicknexs.com/micro-drama-app-marketing-distribution/)), and DramaBox-style hooks work by firing an emotional trigger — moral outrage, romantic tension, empathy shock, power reversal — *before* giving context ([DramaBox analysis](https://www.dramaboxdb.com/content/critique/6163_dramabox-from-short-attention-to-strong-emotion)).

Everything above fits inside 3 build hours except P2A (corpus sourcing risk) and cross-episode stitching, both already flagged.
